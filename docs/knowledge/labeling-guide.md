# Knowledge structure and labeling guide

Generated by scripts/build_knowledge.py from config/v2/taxonomy.json, vocabulary.json and label-guide.json. Edit those sources, not this file.

Project codebook; not an official exhaustive UNDP or UNDRR classification

Versioned project codebook. Policy classifications, linked facts, and evidence/processing metadata have separate sections. Classify only substantive supported meaning; lists may be empty.

## Record structure

- **Source and segment:** Immutable document version, language, physical/printed page, section, original text and hash.
- **Evidence:** Exact original quote, aligned English quote and resolvable source locator.
- **Record:** One coherent source claim with one statement type, multiple supported topic/facet labels and linked details. Promises and reported delivery remain separate.
- **Target variants:** Quantities or qualitative deliverables, unit, baseline, deadline, scenario, scope and conditionality.
- **Linked details:** Actors and roles; finance; indicators; support needs; barriers; inclusion; risk-action relationships.
- **Source relationships:** Proposed repetition, revision and conflict links. Preserve source records and count source records; no automatic canonical merging.
- **Finding and report:** Cited synthesis of records; source facts, observations, calculations and analyst suggestions kept distinct.
- **Coverage and provenance:** Processed/excluded/unreadable segments, missing reasons, source/method versions and validation findings.

## Domains and topics

A domain is a sector; a topic is the only subdomain level. Select supported topic IDs; the application derives their domains. Cross-domain topics do not create duplicate commitments.

# Policy labels

## Objectives (`objectives`)

What policy purpose is evidenced?

Choose only source-supported purposes; a NAP location alone does not establish adaptation. Mitigation here means emissions reduction or carbon sinks. Disaster-impact mitigation (such as flood mitigation) belongs to disaster risk reduction when supported; a word match alone is insufficient.

| Value | Meaning |
|---|---|
| `adaptation` — Adaptation | Adjustment to actual or expected climate effects and their consequences. |
| `mitigation` — Climate mitigation | Reduction of greenhouse-gas emissions or enhancement of carbon sinks. |
| `disaster_risk_reduction` — Disaster risk reduction | Prevention of new disaster risk, reduction of existing risk, or management of residual risk. |
| `unspecified` — Unspecified | The purpose is relevant but cannot be determined from this evidence. |

## Statement types (`record_kinds`)

Choose one type per coherent claim. Split independently actionable measures and promises from observations. Keep target variants together. Historical periods belong in dates; templates belong in coverage exclusions. An actionable source priority is a commitment with its priority wording retained in details.

| Value | Meaning |
|---|---|
| `context` — Context / finding | A source-described condition, risk, need or background finding without an actionable undertaking. |
| `priority` — Priority | An explicitly important area or goal without a concrete undertaking. |
| `proposal` — Proposal / recommendation | An action suggested, advised or considered without established adoption. |
| `commitment` — Commitment | An attributable undertaking to act or achieve a target, including qualitative and conditional commitments. Preserve source authority and draft/adopted status. |
| `implementation_observation` — Implementation reported | An attributed report of activity or delivery, such as installation or programme operation; not independent verification. |
| `result_observation` — Result reported | An attributed report of an outcome associated with an action; preserve period and method. Delivery of an output alone is implementation. |

|---|---|
| `found` — Found | Supported findings were identified. |
| `not_found_in_scope` — Not found in scope | No relevant finding was found within the declared processed scope. |
| `not_applicable` — Not applicable | The section is not applicable to this source configuration. |
| `not_processed` — Not processed | The required processing has not been completed. |

## Relation kinds (`relation_kinds`)

How do statements relate across sources?

Relationships require paired evidence. Preserve disagreements and do not count translations as new commitments.

| Value | Meaning |
|---|---|
| `same_variant` — Same variant | The statements express the same substantive target variant. |
| `translation_equivalent` — Translation equivalent | The statements are verified equivalents across languages. |
| `revises` — Revises | A later statement modifies an earlier one. |
| `supersedes` — Supersedes | Evidence establishes that one statement replaces another. |
| `related` — Related | The statements are substantively linked without a stronger verified relationship. |
| `contradicts` — Contradicts | The statements make incompatible assertions within a comparable scope. |
| `not_restated` — Not restated | A prior statement is not found again in the reviewed later scope; this is not proof of repeal. |
| `parent_child` — Parent child | A broader commitment contains a more specific action or target. |
| `unresolved` — Unresolved | The relationship cannot yet be resolved. |

## Change kinds (`change_kinds`)

What changed across eligible editions?

Apply only to established earlier/later scope. Missing processing cannot establish a change.

| Value | Meaning |
|---|---|
| `added` — Added | A statement appears in the later reviewed edition and is not found in the earlier scope. |
| `restated` — Restated | The substantive statement is retained. |
| `number_changed` — Number changed | A numeric value changed; retain both bases and units. |
| `scope_changed` — Scope changed | Geographic, sectoral or other scope changed. |
| `condition_changed` — Condition changed | A condition or scenario changed. |
| `not_restated` — Not restated | The earlier statement is not restated in the later reviewed scope. |
| `withdrawn` — Withdrawn | The source explicitly establishes withdrawal. |
| `unresolved` — Unresolved | The change cannot be characterized reliably. |

## Unmapped terms and changes

Keep irrelevant facets empty. If a relevant concept has no fitting option, preserve the source term and evidence in unmapped_terms. Do not force it into a default sector or invent a permanent ID. Edit the versioned taxonomy/vocabulary and guide, validate and rebuild; new runs use the new configuration. Existing reports retain their original method versions.
