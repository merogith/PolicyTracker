# Structured output contracts

**New implementation target: [v2 contracts](v2/README.md).** The files in this directory root are legacy v1 contracts. `scripts/build_contracts.py` regenerates only those legacy files. Use `scripts/build_v2_contracts.py` and `scripts/check_v2_pack.py` for the v2 risk/resilience knowledge model, feature outputs and automatic-publication metadata. The legacy registry has not been migrated.

The JSON schemas are generated by `scripts/build_contracts.py` and versioned in Git. They are local data contracts; each provider adapter must check whether its strict-output subset accepts the schema and remove only envelope metadata if necessary. Do not remove substantive constraints to make an unsupported provider appear compatible.

`extraction` contains evidence items, dated statements, target variants, typed additional facts and a per-segment coverage ledger. Evidence IDs resolve to exact original quotes on physical PDF pages. `field_support.field_path` is a JSON Pointer relative to its statement, for example `/targets/0/conditionality`. Local code must verify the pointer exists and supporting evidence belongs to authorized input sources.

Numbers use decimal strings for lossless locale normalization; the original quotation remains authoritative. Validate decimal syntax, units, ranges and any transformations semantically. Dates permit ISO dates, years, quarters or raw intervals as strings because sources differ; normalization must preserve the original granularity.

Evidence structure alone does not establish factual correctness. Additional checks must verify quote spans, foreign keys, country/party scope, condition attachment, no false duplicate merges, translation coverage and every cited headline. `performance_status` is restricted to `not_assessed` at extraction; a future performance-assessment contract must require observations, method and date.

Report findings reference statements/evidence rather than embedding new untraceable policy facts. Server-generated provenance, hashes, ownership and review state wrap model outputs in the report bundle; models cannot manufacture trusted metadata. Triage, reconciliation and quality schema results are proposals and never publication receipts.

Unknown values are `null`; empty arrays mean no items were returned for that field in this task, not proof that nothing exists nationally. Production release validation must distinguish no documents, incomplete processing and complete processed scope with no findings.
