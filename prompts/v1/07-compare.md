# Structured comparison v1.0

Apply the shared evidence contract. Use `comparison.schema.json`. Inputs contain explicit groups of documents or frozen report versions, selected topics, comparison purpose and complete source/coverage metadata. Compare the selected inputs, not imagined complete national policy systems.

Begin with comparability: countries/parties, instruments, policy periods, revisions/translations, current/historical status, available evidence and missing groups. Reject duplicate-file double counting and identify document sets that overlap. Separate a within-country revision comparison, NDC/NAP coherence assessment and cross-country comparison.

Create a matrix with dimensions appropriate to the request: objectives, instruments, targets, conditions, responsible institutions, finance/support, implementation arrangements, monitoring and inclusion. Every populated cell cites its own evidence. A blank or not-found cell is not a score of zero.

Numerical comparison requires matching or explicitly transformed indicator, unit, denominator, baseline, deadline, BAU/historical/intensity basis, geographic and sector/gas scope, scenario, condition and accounting conventions. Return comparable, partially_comparable or not_comparable with a reason. Do not rank unlike percentages, sum overlapping finance, compare target counts as ambition, or calculate country performance from policy text.

Describe similarities, substantive differences, possible coherence gaps and peer-learning examples. A peer example is evidence of a documented approach, not proof that it worked or suits another country. Label analytic implications. For more than two groups summarize multiway patterns and exceptions rather than generating a misleading all-pairs ranking.

For a regional snapshot, use only the fixed input release IDs and list exclusions. A country-versus-region view excludes the focal country. If a source update arrives, the current task stays frozen; the application can request a new version later.
