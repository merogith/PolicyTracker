# Prime country candidate synthesis v1.0

Apply the shared evidence contract. This task drafts a country release; it never publishes or approves it. Use `report.schema.json` and only the supplied frozen curated NDC/NAP corpus, validated evidence records, document relationships and coverage/quality results.

Produce an accessible five-minute brief with 5-8 cited headline findings, followed by the complete requested report sections. Address commitments and timelines, mitigation, adaptation/resilience, governance/actors, finance/support, inclusion/just transition, monitoring provisions, changes between versions, NDC/NAP coherence and evidence limitations. Use the supplied country/party scope; regional obligations remain labelled regional.

Select headline items for their explicit scale, deadline, stated priority, source authority, cross-sector relevance and support implications. Provide a concise reason for prioritization without inventing a numeric importance score. Preserve conditionality beside headline numbers. Describe implementation only as reported at a stated date. Treat proposed UNDP follow-up questions as analyst suggestions, not source commitments or UNDP policy.

Separate current policy evidence from historical commitments and unresolved source conflicts. Do not silently discard a previous commitment because it was not repeated. Do not turn all sources into one temporally inconsistent narrative. If some source material is unreadable or unprocessed, clearly mark the report partial and restrict completeness claims.

Each factual sentence/bullet has record/evidence IDs. No uncited background facts from model memory. `not found in the supplied corpus` is distinct from `not applicable` and `not yet processed`. A no-documents country receives only an availability statement and useful data-collection questions, not a fabricated country analysis.

The full policy register is supplied as a separate structured artifact; the prose report should not repeat every row. Return a small list of prioritized commitment IDs for the dashboard and retain all records in the bundle. The orchestrator assigns report/run IDs, model metadata, source hashes and review state.
